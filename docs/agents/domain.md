# Domain docs

This repo has one context: `GLOSSARY.md` at the root and ADRs under `docs/adr/`.

Before exploring or changing the product, read the glossary and the ADRs relevant to the work. Use the glossary's terms in specs, issue titles, implementation, and tests. If a proposed change conflicts with an ADR, identify the conflict explicitly rather than silently overriding it.

If a domain document is absent, proceed without creating an empty placeholder. Domain terms and ADRs are added when a real term or decision is resolved.
