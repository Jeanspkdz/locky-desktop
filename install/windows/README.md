# Windows browser setup

`pnpm setup:dev` configures a local development install for the current Windows user. It writes native-messaging registrations and private-browsing policies for Chrome, Brave, Edge, and Firefox, and adds Locky to the user's startup entry. It does not need administrator rights. Windows starts Locky in the background; closing its settings window leaves protection running. Launch Locky again to reopen settings. Development runs report unhealthy integrations but do not close browsers by default.

After setup, load the unpacked Chromium extension from `extensions/chromium` using `chrome://extensions`, `brave://extensions`, and `edge://extensions` respectively. Enable Developer mode and choose **Load unpacked**. In Firefox, open `about:debugging#/runtime/this-firefox` and load `extensions/firefox/manifest.json` as a temporary add-on; Firefox removes temporary add-ons at restart, so load it again each time. A browser without the extension is closed after the 15-second integration startup grace period.

Run `pnpm smoke:native-host` to verify that the registered native host can exchange a state request with the desktop app. This smoke test does not load the browser extension or replace an installed-browser navigation check.

`pnpm package:win` creates a portable Electron package at `dist/win-unpacked` and includes `Install-Locky.ps1`. The output directory must not already exist; remove or rename it yourself before creating another package. To install or repair, open PowerShell as administrator under the same Windows account that uses Locky, then run `pnpm install:win` from the repository or run `Install-Locky.ps1` from the package folder. It installs under Program Files, registers the per-user native host, startup entry, and browser policies, then starts Locky. Re-running it repairs package files and registrations.

The installer keeps extension loading explicit for this development-only local distribution. Load the Chromium extension from the installed package in Chrome, Brave, and Edge. Load Firefox's temporary add-on from the installed package and reload it after Firefox restarts. Locky reports missing or stale integrations in its settings window; packaged builds close only the affected browser after the 15-second startup grace period. Other applications and browser families are left running.

`register-browser-hosts.ps1` builds a small local native-host executable and a Win32 window monitor, then writes per-user native-messaging registrations, the Windows login startup entry, and private-browsing policies for Chrome, Brave, Edge, and Firefox. The native host forwards browser messages to Locky's local named pipe and exits if that pipe disappears so the extension can fail closed and reconnect. The window monitor lets Locky place one owned overlay over each visible Chrome, Brave, or Edge window; other applications remain outside those browser-owned windows. The native messaging manifest uses no custom command-line arguments. It does not change system-wide App Control rules. The extension ID for Chromium is fixed by the public key in its manifest.

Firefox's local add-on is temporary and must be loaded again after each restart. Opera Stable, Opera GX, and other Opera variants are not configured or declared protected; each must pass real blocking, native-messaging, and private-mode checks before being added.

In a packaged build, if a browser has no recent successful extension heartbeat, Locky closes only that browser and leaves a repair notice in its settings window. The first 15 seconds after startup are allowed for the extension handshake. Development runs do not close browsers by default; set `LOCKY_ENFORCE_UNHEALTHY_BROWSER=1` only in a dedicated test session.
